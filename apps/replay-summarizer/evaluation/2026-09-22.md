# Replay summary pilot — 2026-09-22

Queried local PostgreSQL: 37,683 recordings, no existing inline summaries. Exported
two complete recordings to `/tmp/replay-evaluation`: a 37.811-second desktop
analytics visit and a 94.533-second mobile media-site visit. No evaluation summary
was published to the database. Used the cached `rrweb2video-current` Linux image
for rendering and added the original-time footer with FFmpeg; this was a model
input pilot, not a rebuilt-production-image end-to-end deployment test.

## Rendering

| Sample | 3 FPS / 8× | 3 FPS / 1× |
|---|---:|---:|
| Desktop | 16 frames / 5.33 s | 115 frames / 38.33 s |
| Mobile | 37 frames / 12.33 s | 285 frames / 95.00 s |

Normal speed preserves much more interaction context. Use 3 FPS / 1× as the
starting default, with configurable overrides. This does not establish an optimal
FPS or guarantee that a model consumes all encoded frames.

## Final four-call comparison

Same portable schema, prompt and recorded interaction evidence; 3 FPS / 1×.
Costs and latency are reported by the client/provider, excluding rendering.

| Model | Desktop: USD / seconds | Mobile: USD / seconds | Result |
|---|---:|---:|---|
| GLM 5.3 Flash | $0.00485090 / 21.96 | $0.00218970 / 6.57 | Valid outputs; no pain points on either recording |
| Gemini 3.8 Flash | $0.00390900 / 8.01 | $0.01115175 / 11.77 | Valid outputs; desktop had no pain points, mobile flagged the persistent menu |

Four accepted calls total **$0.02210135**. This is not total spend for the pilot:
earlier diagnostic calls and invalid outputs are excluded. Detailed responses,
usage, provider routing, and the evaluated prompt snapshot are in
`/tmp/replay-evaluation/final`.

Gemini's mobile finding remains questionable: menu persistence alone does not
prove a defect or that the user attempted to dismiss it. Its 0.85 confidence is not
a calibrated probability. GLM's mobile prose was too close to a raw event log and
included node IDs, so the final prompt additionally prohibits those implementation
details in user-facing summaries; that final prose-only instruction was not rerun.
Keep GLM as the configurable default for now; this small pilot does not justify a
blanket model switch or an automatic confidence threshold.

## Earlier failures that informed the changes

- Schema string limits, a large array bound, and a duration-specific numeric bound
  made Google's structured decoding fail. Gemini 2.5 returned an explicit
  too-many-states error. The portable schema succeeded after removing those
  constraints; local validation retains all limits.
- GLM initially returned valid JSON with an unfinished sentence and, in another
  run, described only the end state. JSON validity alone does not prove quality.
- Qwen 3.8 Flash took about 104 seconds on desktop and speculated that a map tooltip
  represented a blocked action. Its mobile request did not finish a complete
  summary after about 133 seconds. It was not rerun with the final prompt.
- Video-only Gemini labelled touch gestures around 19 and 87 seconds failed clicks.
  The original rrweb events show touch starts without click events there. The
  bounded, value-free interaction timeline was added to address that ambiguity.

## Next evaluation

Use a labeled set with genuine failures, successful retries, masked forms,
cross-tab handoffs, long sessions, and ordinary mobile scrolling. Blind-review
false-positive pain points, missed issues, factual coverage, and timestamp error.
Repeat each model/profile pair to measure variability. Neither these two samples
nor self-reported confidence establish precision or recall.
